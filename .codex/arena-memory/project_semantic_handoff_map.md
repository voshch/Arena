DURABLE FACT: humansim IS drivable headless for in-process rollouts. `AgentManager.tick()` (arena_humansim/core/agent_manager.py) is a plain method run in a bare loop; seeded/deterministic (RNG); reads ped trajectories from `_pool.pos/theta/vel`; needs only rclpy.init() + built arena_humansim_msgs, NO gz/isaac/spin. Robot can be scripted (`_world_state_callback` per tick) or a policy agent (kind=1, policy=straight/sfm/ML). Determinism proven by tests/integration/test_determinism.py. Dynamics need the world's walls (scenario.walls), so a rollout still needs a finalized world.

ADVERSARIAL REALITY (3 fresh reviewers, verified vs code) -- all three plans were over-optimistic; DO NOT start coding on the rosy framing:
- CONDITIONS EVAL (Plan 1, DUCANH): reshaped correctly to NOT-online = pure eval core (lift out of arena_evaluation into arena_simulation_setup.shared, ROS/polars-free) + SampleSource protocol + McapSampleSource (offline) + RolloutSampleSource (humansim). BUT: it's a REWRITE of the atom->series layer, not a "lift the pure core" (only parse_atom + _operator_verdict are truly pure). Offline vs rollout verdicts DIVERGE on two axes: aligner ZOH (topic_aligner tolerance_ns=100ms) vs exact ticks, AND the zone-set (now fixed, see [[semantic-layer-v1]] zone bug). Robot-path semantics resolved: use a humansim policy or the heavy planner (both available) so ped<->robot timing is genuine, not a scripted proxy. v1 = ped-membership atoms; door/elevator entity atoms need composing the arena_runtime mechanism `_tick` (async, needs full MechanismITF stub + SemanticsManager attach) = a real async co-sim harness, NOT "just a driver". Existing condition tests preload _world_cache so they DON'T guard the real integration.
- HOI (Plan 2, Tai): the "joint_state SSOT -> Isaac/RViz free" framing is DEAD. The 20-DOF gait rig (gait.py JOINT_NAMES) physically can't express sit/grasp/press: no root-height DOF (z hardcoded 0), hip flexion capped 0.7 rad (seated ~1.5), shoulder yaw/roll reserved-always-0 (Isaac bone_map drops them, RViz rig clobbers to pi/2), no wrist/fingers. HOI needs a NEW pose channel + un-reserved DOFs + a from-scratch pose producer. humansim MotionAnimation emits Pose2D (no skeleton) and never reaches the wire; the speed->animation_state map is task_generator (OURS) at arena_humansim.py _agent_states_to_pedestrians, not the engine. Interaction-trigger coupling spans 4-5 packages, not a _semantics.py edit. Gated on M4 anchors.
- M4/ASA (Plan 3, us): UNDER-SCOPED ~an order of magnitude. "Lift binding:joint / trigger:contact reservations" is a CROSS-SIMULATOR PHYSICS FEATURE -- the sim interface (MechanismITF) has only spawn_box/move_box, NO joint control, NO contact sensor; hinged doors already fall back to teleport; pressure-plate "contact" is a proximity check. ASA tag grammar is `[a-z0-9_]+` (CANNOT encode joint axes/limits/poses) so articulation needs a NEW structured schema + per-asset authoring across the catalog (a content project). facet->preset map is circular (needs an `openable` facet that doesn't exist; hoi is flat lie/see/sit/touch). Auto-attach targets the wrong layer (doors/elevators are procedural World geometry with no annotation; annotated obstacles are placed at RUNTIME by task_generator). RECOMMENDED de-scope: a minimal 2D anchor model (approach + interaction pose, NO physics articulation) is enough to unblock HOI; true articulation/contact is a separate large track to defer.
