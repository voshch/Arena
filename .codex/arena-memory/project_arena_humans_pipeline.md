- Headless MakeHuman: no CLI export exists, driver (mh_export.py) installs the auto-export plugin into ~/Documents/makehuman/v1py3/plugins (inert without ARENA_HUMANS_* env), runs the app with QT_QPA_PLATFORM=offscreen. Plugins load AFTER libraries register .mhm loadHandlers and BEFORE the window/GL. User plugins MUST be whitelisted in settings.ini activeUserPlugins, driver ensures it.
- MakeHuman 1.3 needs numpy < 2 (npz mesh loader uses removed tostring), hence repo-local .mhvenv (--system-site-packages + numpy<2), driver auto-picks it. Offscreen GL render-loop errors in makehuman.log are harmless.
- cmu_mb naming traps: DAE skeleton has 31 joints with PLAIN CMU names (LHipJoint) matching real CMU BVH; MakeHuman's OWN BVH export wraps 6 helpers in __-prefixed PARENT joints, do not strip prefixes. Clips validate against the skin DAE joint set (subset rule). cmu_mb renames LeftHandIndex1/RightHandIndex1 -> LeftHandFinger1/RightHandFinger1 (_CMU_RENAMES in cli).
- MakeHuman DAE skin joints are IDREF_array, not Name_array; arena_isaac peds/convert.py still needs IDREF_array + multi-mesh + textures + BVH clip parsing to consume these bundles in Isaac.
- CMU clips: scripts/fetch_cmu.sh -> data/cmu/, scale 0.056444, 07_01=walk, 82_08 head=idle (trim [0,300]). Relative recipe bvh paths resolve against data root (--data, $ARENA_HUMANS_DATA, ./data).
- Container (Dockerfile + docker.sh): ubuntu 24.04 + MakeHuman PPA debs, apt numpy 1.26 (never pip-upgrade), baked /opt/mhhome with MH_HOME_LOCATION=/opt/mhhome/Documents; baked settings.ini MUST carry matching "version" AND "_versionSentinel" or MakeHuman silently discards the plugin whitelist. Mounts: /recipes ro, /data ro, /out rw. Image needs a rebuild since the rename (COPY paths now src/).
