2026-07-19, two reproductions on feature/ped-gui (isaac, peds + `arena human` panel, one with robot+nav2, one without). Symptom: whole `/World/env_N` (walls, floor, peds, robot) deleted mid-run at ~2.5-3 min of sim uptime, plus `getVelocities` invalid-view spam when a robot articulation is present. ROOT CAUSE, both stages confirmed:

**Stage 1, Isaac service starvation:** [run_isaacsim.py](arena_isaac/arena_isaac/arena_isaac/run_isaacsim.py) mainloop drains ROS services with a single `rclpy.spin_once(controller, timeout_sec=0)` per render frame, all arena services share it, QoS depth 2000. Possession/colocation traffic (20 Hz full-sync `UpdatePedestrians` + stream relays + engine feedback) arrives faster than the frame rate drains, queue backs up over ~2-3 min, response latency climbs past the 60 s ClientWrapper timeout. tg keeps firing 20 Hz regardless (fire-and-forget task pile = "exception was never retrieved" spam at shutdown), so the queue never recovers. Explains identical time-to-death across runs (148 s and 178 s). Different services = separate queues, which is why arena_node's `DeletePrims` still executed promptly while `UpdatePedestrians` was minutes deep.

**Stage 2, tg executor wedge:** `arena_rclpy_mixins` `create_subscription` wraps async callbacks with `syncify` -> `wait_for` -> `run_coroutine_threadsafe(...).result()`, which BLOCKS the rclpy executor thread and holds the callback group until the coroutine finishes. `_on_human_stream` (20 Hz `human/stream` sub, default MutuallyExclusive group) awaits `relay_pedestrian_update` -> `/isaac/UpdatePedestrians`. Once isaac latency exceeded ~5 s, the default group stayed locked, which froze the heartbeat wall timer AND `_cb_shutdown_request` (same group) -> arena_node `sweep_verdict` heartbeat_timeout (5 s budget) -> `_evict` -> `cleanup_namespace` -> `isaac/DeletePrims /World/env_0` wipes everything. Proof: tg unwedged and processed the pent-up shutdown_request at the exact instant the 60 s timeouts expired (23:59:03.5 hang -> 00:00:03.5 exit).

Fallout when a robot exists: articulation deletion invalidates the global PhysX tensor SimulationView -> per-tick getVelocities error spam + odom TF freeze -> nav2 "Transform data too old" cascade. Cosmetic spawn-time burst of the same error (articulation init) is unrelated and self-heals.
